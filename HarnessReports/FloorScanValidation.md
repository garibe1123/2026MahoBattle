# 바닥 탐색 변경 검증 현황

실제 CPU 시간·GC Alloc 비교 결과는 아직 확보되지 않았으며, 성능 개선 완료로 판정하지 않는다.

## 수정 파일과 영향 범위

- `Assets/Script/BattleRework/Presentation/BattleShowPresentationManager.cs`: 앞선 수정에서 자동 탐색의 기존 장식 대상을 제외하고, 새 장식 대상이 없을 때 목록 생성과 점유 셀 계산을 생략했다. 이번 이어서 작업에서는 이 파일을 추가 수정하지 않았다.
- `Assets/Editor/HarnessFloorScanComparison.cs`: 현재 Play 중인 동일 전투 상태에서 원래 경로와 수정 경로를 비교하는 에디터 메뉴를 추가했다. SO·공개 API·풀링 및 씬·프리팹·프로젝트 설정은 변경하지 않았다.

## 검증 결과

| 항목 | 코드에서 확인한 경로 | 실제 실행 결과 |
| --- | --- | --- |
| CPU 시간·GC Alloc | 에디터 메뉴가 같은 프레임에서 양쪽 경로를 교대로 호출하고 평균 시간과 메인 스레드 관리 할당을 기록한다. | 미측정. 개선 여부 미확정. |
| 룰렛 중 기존 베이스 스프라이트·색상 | `Update`와 `DecorateAllLiveFloor`의 기존 RuleRoulette 분기를 유지했다. | 미검증. 룰렛에서 메뉴를 실행하면 기존 베이스 스냅샷을 비교한다. |
| 새 블록 장식 | `DecorateAllLiveSlidingBlocks`는 `PresentationTemplate`이 없는 대상을 계속 처리하며, 점유 계산에는 기존 전체 `blocks`를 전달한다. | 미검증. 측정 메뉴는 장식 완료 상태만 비교하며 새 블록 생성 검증을 대신하지 않는다. |
| 도킹 시 기존 바닥·손잡이 배치 | 기존 장식 대상은 다시 조립하지 않고 `SubscribeDockImpact` 호출을 유지한다. | 실제 도킹은 미검증. 메뉴의 같은 프레임 전후 비교는 도킹 이벤트 검증을 대신하지 않는다. |
| 명시적 Refresh | `rebuild == true`이면 기존 장식 대상 생략 분기를 우회한다. `RefreshSlidingFloorArt` 및 룰렛 베이스 보호 경로를 유지했다. | 미검증. Refresh 호출·코루틴 완료 후 외형 확인 필요. |
| 컴파일 | 프로젝트 참조의 C# 9 설정과 설치된 Unity 참조 DLL의 `GetAllocatedBytesForCurrentThread`·에디터 콜백 API 심볼을 확인했다. | Unity 컴파일 성공 여부 미검증. 빌드·테스트·설치 명령은 실행하지 않았다. |

위 코드 확인은 앞선 제한적 소스 확인을 바탕으로 하며, 실행 통과를 의미하지 않는다.

## 실측 절차와 산출물

1. Unity에서 기존 전투를 Play하고 새 블록 장식이 완료될 때까지 기다린다.
2. `Tools/Harness/Measure Live Floor Scan`을 실행한다. 준비 중 외형 변화가 발견되면 비교가 취소되므로, 장식 완료 후 다시 실행한다.
3. `HarnessReports/FloorScanComparison.md`에 전투 씬·상태·방·블록 수·템플릿·화면 크기·CPU 정보, 양쪽 경로의 CPU ms/scan·GC Alloc B/scan과 감소 여부가 기록된다.
4. 룰렛에서도 같은 메뉴를 실행한다. 보고서는 덮어쓰지 않고 각 실행 결과를 추가한다.
5. 새 블록 생성, 실제 도킹, 명시적 Refresh는 별도로 실행해 확인해야 한다. 해당 실행 근거가 없는 항목은 미검증으로 남긴다.

각 경로를 8회 준비한 뒤 32회씩 20개 배치를 AB/BA 교대로 실행한다. 같은 메인 스레드·프레임의 고정된 전투 상태에서 비교하며, 시간과 할당 측정 구간에는 스냅샷·리플렉션·보고서 작성을 포함하지 않는다. 전투 전체 프레임 성능이나 GPU 비용을 측정하는 도구가 아니다.

현재 작업에서 `Temp/HarnessFloorScanComparison.request`로 측정을 요청했다. 에디터가 새 스크립트를 로드하고 기존 전투가 Play 중이면 한 번 비교하며, 씬을 바꾸거나 Play를 자동 시작하지 않는다. 성공 시 요청을 삭제한다. 결과 파일이 없으면 측정이 완료된 것으로 간주하지 않는다.

## 실행 환경 확인과 제한

`Library/EditorInstance.json`에서 Unity 6000.0.23f1과 해당 프로젝트 프로세스가 확인됐다. 따라서 이전의 Unity 미설치 설명은 정확하지 않다. 다만 이 세션에는 Unity 제어 도구가 없고, 확인된 Unity 프로세스의 메인 창 핸들이 모두 0이었다. 프로세스 상세 정보 및 외부 에디터 로그 접근도 거부됐다. 새 에디터 스크립트의 실행 콜백·실측 보고서는 아직 확인되지 않았다.
